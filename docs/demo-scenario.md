# 시연 시나리오

발표용 데모 순서 (약 8~10분). 사전 조건: 원격 DB 접속 가능, `.\run.ps1` 로 3개 서비스 기동.

## 0. 준비 (발표 전)

```powershell
.\run.ps1                                                        # 서비스 기동
powershell -ExecutionPolicy Bypass -File .\scripts\integration-test.ps1   # 전체 동작 사전 점검 (29건)
```

- 학습 모델이 없으면: `cd ai-service; .venv\Scripts\python scripts\train_model.py --epochs 5`
- 샘플 이미지가 없으면: `cd ai-service; .venv\Scripts\python scripts\generate_sample_dataset.py`

## 1. 시스템 소개 (1분)

- 아키텍처 한 장: React(5173) → Spring Boot(8080) → FastAPI(8000) + 원격 PostgreSQL/PostGIS
- Swagger 열어 API 규모 시연: http://localhost:8080/swagger-ui.html

## 2. 로그인과 권한 (1분)

1. http://localhost:5173 접속 → `user / user1234!` 로그인 → 조회 메뉴만 표시됨을 보여줌
2. 로그아웃 → `admin / admin1234!` 로그인 → 데이터 등록·AI 예측·IDW 보간 메뉴 추가 표시

## 3. 대시보드 (1분)

- 최신 평균 PM2.5·등급 배지·관측소 수·최근 예측/보간 건수 카드
- 시간별 평균 PM2.5 차트(24시간), 관측값 vs 예측값 비교 차트

## 4. 데이터 관리 (1분)

1. 관측 데이터 목록: 관측소 필터·페이지네이션·등급 배지
2. 데이터 등록: 새 관측값 1건 등록 → 목록에서 확인

## 5. AI 예측 (2분)

1. AI 예측 메뉴 → 관측소 선택, `data/sample/dataset/images/`의 PNG 업로드, 환경값 입력
2. 예측 실행 → PM2.5 예측값·등급·해당 관측소 실제 관측값 비교 표시
3. 모델 성능 메뉴 → 회귀 지표(MAE/RMSE/MAPE/R²)와 등급 지표(정확도·혼동행렬) **구분** 강조
4. (멘트) 현재 지표는 합성 데이터 파이프라인 검증 결과이며 실측 데이터로 교체 예정

## 6. IDW 보간 (1분)

1. IDW 보간 메뉴 → 기본 지점(서울숲) + 위치 1개 추가 → 보간 실행
2. 결과 카드(값·등급)와 이력 테이블
3. (멘트) Haversine 거리 기반, Python 기준 구현과 1e-6 이내 일치 검증

## 7. 3D 지도 (2~3분) — 하이라이트

1. 3D 지도 메뉴 → 수도권 상공 뷰, 관측소 마커 + 색상 격자(3x3x2)
2. 격자 클릭 → 상세 팝업(구분·PM2.5·등급·시각·좌표)
3. 레이어 토글: 관측값/AI 예측값/IDW 보간값 켜고 끄기
4. "관측소로 이동" 드롭다운 → 카메라 비행
5. **시계열**: 기간 확인 → [시계열 로드] → ▶ 재생 → 격자 색·라벨이 시간에 따라 변화
6. Timeline 드래그로 특정 시간 이동, 배속 조절

## 8. 마무리 (30초)

- 통합 테스트 29건 자동 검증 결과 화면
- 향후 계획: 실측 데이터 수집, Modified IDW, 전이학습 실험

## 예상 질문 대비

| 질문 | 답변 요지 |
|---|---|
| 예측 정확도가 낮은 이유는? | 합성 데이터 120장·5 epochs의 파이프라인 검증 결과. 실측 데이터·전이학습 적용 시 개선 |
| 왜 IDW인가? | 관측소 수가 적은 MVP에 적합, 구현·검증 용이. Modified IDW로 확장 계획 |
| 등급 기준은? | 한국 환경부 기준, 3개 서비스 모두 설정 파일로 관리 (하드코딩 없음) |
| 데이터 누수 방지는? | 날짜 단위 분리 + 자동 검증 게이트, 정규화도 train으로만 fit |
