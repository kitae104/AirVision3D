# 대시보드 지역 선택(구 단위 필터) 설계

- 날짜: 2026-07-22
- 대상 Phase: 25
- 상태: 사용자 설계 승인 완료

## 목적

대시보드가 현재 "어느 지역 기준인지" 불명확한 문제를 해소한다.
사용자가 **인천 전역** 또는 핵심 3구(**미추홀구·남동구·연수구**) 중 하나를 선택하면,
자체 데이터 기반 통계·차트가 선택 지역 기준으로 재집계되어 표시된다.

## 결정 사항 (사용자 확인 완료)

1. **필터 범위**: 자체 데이터(관측소·관측값·AI 예측·보간)만 구 단위 필터.
   공공 데이터(에어코리아 실측·예보, 기상청)는 시/도 단위 자료이므로 "인천 전역" 표시를 유지하고,
   카드 그룹에 "인천 전역 (시/도 단위 자료)" 라벨을 붙여 혼동을 방지한다.
2. **상태 범위**: 대시보드 전용 로컬 상태(`useState`). 전역(Zustand) 공유는 하지 않는다.
   지도 페이지의 기존 카메라 이동 버튼과는 독립이다.
3. **구현 방식**: DB 컬럼 + 백엔드 필터. 프론트 전용 매핑이나 PostGIS 경계 판정은 사용하지 않는다.

## 구성 요소

### 1. DB — Flyway `V5__site_district.sql`

- `ALTER TABLE observation_sites ADD COLUMN district VARCHAR(30);` (NULL 허용)
- 기존 시드 관측소에 구 값 UPDATE:
  - 미추홀구: `미추홀주안`, `미추홀용현`
  - 남동구: `남동구월`, `남동논현`
  - 연수구: `연수동춘`, `연수송도`, **`인천송도`(V2 시드, 연수구 소재)**
  - 그 외(서울·수원·성남·고양 등 V2 시드)는 NULL 유지 → 어떤 구 필터에도 포함되지 않음
- 행 수가 적어 인덱스는 추가하지 않는다.

### 2. 백엔드 — 선택적 `district` 파라미터

기존 엔드포인트에 optional `@RequestParam district` 추가. 미지정 시 기존과 완전히 동일하게 동작한다.

| 엔드포인트 | 변경 |
|---|---|
| `GET /api/dashboard/summary` | `?district=` 추가. 해당 구 관측소만으로 평균 PM2.5·관측소 수·최근 예측 수 집계. 단 **최근 보간 수는 항상 전체 기준** — IDW 보간 결과는 전체 관측소 기반 격자 표면이라 구에 귀속되지 않는다. 구 선택 시 프론트 카드에 "전체 기준" 라벨을 표시한다 |
| `GET /api/dashboard/hourly` | `?district=` 추가. 해당 구 관측소의 시간별 평균만 반환 |
| `GET /api/predictions` | `?district=` 추가. 관측소(site) 조인으로 필터 (관측 vs 예측 차트용) |

- `ObservationSite` 엔티티에 `district` 필드 추가, sites 응답 DTO에 노출.
- 검증: 허용 값은 `미추홀구`, `남동구`, `연수구` 3종. 그 외 값은 400 Bad Request.
  (허용 목록은 백엔드 상수로 정의)

### 3. 프론트엔드 — DashboardPage

- 상단에 세그먼트 버튼 그룹: `[인천 전역] [미추홀구] [남동구] [연수구]` (기본값: 인천 전역)
- 선택 상태는 `useState<string | null>` (null = 인천 전역)
- 구 선택 시:
  - 통계 카드 5개, 시간별 평균 PM2.5 차트, 관측 vs AI 예측 차트를 `district` 파라미터로 재조회
  - 페이지 제목 옆에 기준 지역 표시 (예: "대시보드 — 미추홀구 기준")
- 공공 카드 4종 + 공공 추이 차트 2개는 재조회 없이 유지, 그룹 라벨에 "인천 전역 (시/도 단위 자료)" 명시
- 구 이름/목록 상수는 기존 `src/config/sido.ts`의 `INCHEON_CORE_DISTRICTS`를 재사용한다.

## 데이터 흐름

```
[세그먼트 버튼 클릭]
  → district state 변경
  → useEffect 재실행: /dashboard/summary?district=, /dashboard/hourly?district=, /predictions?district=
  → 통계 카드·자체 데이터 차트 갱신
  (공공 데이터 useEffect는 district 비의존 → 재조회 없음)
```

## 오류 처리

- 백엔드: 허용되지 않은 district 값 → 400 (메시지에 허용 목록 포함)
- 프론트: 조회 실패 시 기존 대시보드의 에러 처리 방식(로딩/빈 값 처리)을 따른다
- 구에 관측소가 없거나 데이터가 없는 경우: 카드에 "-" 또는 0, 차트는 빈 상태 (기존 빈 데이터 처리와 동일)

## 테스트 계획

- Backend: Gradle 빌드, `DashboardService` 구 필터 단위 테스트(구 지정/미지정/빈 구), 잘못된 district 400 확인
- Frontend: `tsc` 검사, Vitest 기존 38건 유지 + 선택 UI 동작 테스트, 빌드
- 실행 검증: 백엔드 기동 후 curl로 `district=미추홀구` 응답 확인, 브라우저에서 버튼 전환 확인
- 완료 후 `docs/progress.md`(Phase 25), `docs/user-guide.html`(대시보드 절 + 업데이트 이력) 갱신

## 범위 제외 (YAGNI)

- 공공 데이터의 구 단위 매핑 (에어코리아 측정소-구 매핑)
- 전역 상태(Zustand) 공유 및 지도 페이지 연동
- 구 행정경계 폴리곤 기반 자동 판정
- 3구 외 다른 구 추가 (필요 시 상수·마이그레이션만 확장)
